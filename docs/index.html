01 · Overview

Instruments a robot can operate, not only look at

Survey basis: 200 instruments and modules used in university chemistry teaching and research.

Agents that work in a chemistry lab need more than meshes. They need to know that a fume-hood sash travels 673 mm and stops at 457 mm, that moving a balance's draft-shield door restarts its stability check, and which quantities a policy may observe and which are hidden ground truth kept for evaluation. ChemLab-Assets ships that knowledge together with the geometry.

Every asset is one specific commercial model, built from published brochures, manuals and papers. The models reproduce documented behaviour; they are not manufacturer CAD and have not been calibrated against physical units. Each asset folder contains:

  • Geometry. A GLB for viewing, a URDF with primitive collision proxies for simulators, one OBJ mesh per functional part, and the Blender source file.
  • A contract (asset.contract.json). Components, joints, state slots with units and visibility, callable capabilities with JSON-Schema arguments and declared errors, physical mechanisms, interface points for manipulation, cited sources and the model's known limitations.
  • A runtime. A Python module that implements the contract: time-stepped process models behind describe, read, invoke and poll, separate agent and evaluator views, request-id idempotency and seeded noise.
  • Reference data. Output templates built from published measurements, such as DSC thermograms, Raman, IR and mass spectra, GC retention indices and isotope-ratio standards, each with its citation.

All 198 instruments have been converted to USD and stepped in NVIDIA Isaac Lab through the Matterix framework, with joints driven from runtime state and panel buttons pressed in the scene reaching the runtime. The integration code lives in Matterix and is not part of this release.

02 · Anatomy

One asset, read through its contract

  1. 1

    Exhaust collar

    Interface point exhaust_collar, Ø305 mm. The evaluator sets the building exhaust with exhaust.configure; its true state, exhaust.state, is evaluator-only, so an agent has to infer airflow.

  2. 2

    Sentinel XL airflow monitor

    Readouts velocity (m/s or fpm) and status. Its six keys are prismatic joints bound to monitor.press. Until it is field-calibrated with monitor.calibrate, its reading can sit below the true face velocity.

  3. 3

    Vertical sash

    Prismatic joint sash_joint, 0–673 mm along the 5° face. State slot sash.height_m; capability sash.set, with a stop at 457 mm and a key lock.

  4. 4

    Work zone

    Interface point work_zone, at least 150 mm behind the sash plane. source.place puts open liquids there from a 53-substance vapour library with NIOSH exposure limits.

  5. 5

    Water and gas cocks

    Revolute joints knob_water_joint and knob_gas_joint, 0–90°, driven through fixture.set.

This asset: 39 components · 11 joints · 32 state slots · 32 capabilities (27 implemented, 5 declared unsupported) · 6 readouts · 10 interface points · 14 cited sources · 30 recorded limitations

04 · Quick start

Download an instrument and run it

Tested with Python 3.12 and NumPy 2.3. No simulator is needed to run the behaviour models.
# everything: models, contracts, runtimes and tests (about 1.5 GB)
pip install -U huggingface_hub
hf download MBZUAI/ChemLab-Assets --repo-type dataset --local-dir ChemLab-Assets
pip install -r ChemLab-Assets/requirements.txt

# or one instrument plus the code
hf download MBZUAI/ChemLab-Assets --repo-type dataset --local-dir ChemLab-Assets \
    --include "assets/expansion_batch05/t2_vacuum/esco_efa5uduvw/*" "scripts/*" "examples/*"

Each row of catalog/catalog.csv gives an instrument's folder, so any subset can be fetched the same way.

from asset_runtime import esco_efa5uduvw as rt   # run from the repo root with scripts/ on sys.path

hood = rt.EscoEfa5uduvwRuntime("hood_01")
hood.register_principal("lab", "evaluator")   # sets up the world, sees hidden truth
hood.register_principal("robot", "agent")     # sees what a policy may see
lab, robot = hood.session("lab"), hood.session("robot")

call(lab, "plant.configure", **rt.PLANT_EXAMPLE)       # 295.15 K, 101.325 kPa
call(lab, "exhaust.configure", **rt.EXHAUST_EXAMPLE)   # building exhaust, damper half open
call(robot, "sash.set", height_m=0.457)                 # raise to the 18-inch stop
call(lab, "sim.step", dt_s=30.0)
show("before calibration")

v = call(robot, "anemometer.measure")["face_velocity_m_s"]
call(robot, "monitor.calibrate", reference_m_s=round(v, 3))
call(lab, "sim.step", dt_s=10.0)
show("after calibration")
Output
before calibration   reading 0.28 m/s   alarm low
anemometer           0.309 m/s
after calibration    reading 0.31 m/s   alarm none

call wraps session.invoke(instance_id, capability_id, arguments, request_id) and show reads two agent-visible slots; the full script is examples/quickstart_fume_hood.py. The robot never sees the true face velocity (0.299 m/s, evaluator-only). It finds the low reading, measures the opening with an anemometer and calibrates the monitor, as a technician would.

05 · Provenance & limits

What the models claim, and what they don't

Every capability records its verification level for process, host, scene, robot and hardware.

Each state slot and capability lists the sources it rests on. Manufacturer documents give dimensions, ranges and operating limits; papers, standards and open databases give the measurements behind instrument outputs; where neither exists, the contract states the assumption explicitly. Values a real operator cannot see, such as true exhaust flow or sample composition, are evaluator-only slots: 1,035 of the 6,282 state slots.

786 capabilities are declared but marked unsupported, so an agent can tell a missing feature from a failed call. No capability claims robot-contact or real-hardware validation. Treat the assets as documented, testable behaviour models for embodied-AI research, not as certified digital twins.
